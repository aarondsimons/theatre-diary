# Aaron's Theatre Diary — Project Instructions

## User preferences
- Refer to the user as **Aaron** (he/him) in all thinking and responses.

## Workflow
- **Always show a preview before committing.** Describe what changed and what it will look like. Wait for explicit approval before running `git commit` / `git push`.
- **"Push" or "Push to live"** means Aaron is happy with the preview — go ahead and commit + push to GitHub.
- **Only touch what Aaron asked about.** Don't make unrequested changes to other parts of the code.
- **Revert immediately** when Aaron expresses dislike ("eek," "I don't like that," etc.).

## Technical
- **Use Nominatim for venue coordinates** — never guess or make up coordinates. If a venue isn't in `VENUE_OVERRIDES` and can't be found via Nominatim, ask Aaron.

## Design sensibility
- Aaron is detail-oriented about small visual things: spacing, sizing, border radii, alignment.
- He prefers clean, minimal UI — don't over-engineer or add unnecessary visual complexity.
